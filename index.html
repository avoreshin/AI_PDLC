SECTION 01
01

WHAT IS

AI-FIRST

Не «сколько AI». А «когда».

DEFINITION // 01.01

Это порядок, а не количество.

DEPRECATED

AI-FALLBACK

«Попробую сам → если застряну, спрошу AI»

AI activates: after_failure()

ACTIVE

AI-FIRST

«Начну с AI → если предложение не подходит, поправлю или сделаю сам»

AI activates: step_zero()

Ключ — первый ход. AI-first инженер не «использует AI больше» — он начинает иначе.

CASE STUDY // 01.02

Пример: testing scaffold

AI-FALLBACK · ~3 часа

  • Пишет каркас руками
  • Запутался в моках
  • Использует AI для отдельных кейсов
  • Boilerplate съел весь день

AI-FIRST · ~1.5 часа

  • «Построй scaffold для X с AC: …»
  • Получает результат за минуты
  • Критически дорабатывает edge cases
  • Освобождает 1.5 часа на качество

Та же конечная компетенция · другой entry point

CONSTRAINTS // 01.03

Чем AI-first НЕ является

×

«Делегируй всё подряд» — так теряешь навык. §3.5

×

«Сунь AI в каждую дырку» — для R3+ доменов сначала пишет человек. §4.5

×

«Принимай первое предложение» — опытные пользователи прерывают агента чаще новичков. Они мониторят, а не одобряют.

PARADOX: опытный пользователь = больше ESC, не больше TAB.

Кто инициирует [2/2]

TaskInitiatorHuman role
Code review (первый проход) AI Финальный review для R2+

Research / exploration AI Синтез результатов
Production incident Human AI для логов/корреляций

TIE-BREAKER: критический навык для надзора за AI — человек ведёт. Иначе — AI ведёт.

RCT

SIGNAL

Anthropic 2026 · n=200+ · скорость vs мастерство

RCT // ANTHROPIC 2026

Скорость × мастерство

PatternSpeedMasteryVerdict
Полное делегирование Высокая <40% KILLS SKILL
Отладка без понимания Низкая <40% WORST
Концептуальный запрос + сам кодит Средняя >65% GROWS
Generation-then-comprehension Высокая >65% ★ BEST

G-then-C: AI генерирует → разработчик читает и объясняет себе. Скорость И мастерство.

RITUAL // 03.02 · PRE-COMMIT

3 вопроса перед коммитом

01

Что делает каждая нетривиальная строчка — и почему именно так?

02

Какой edge case сломает этот код?

03

Как я бы написал это сам без AI — хотя бы на уровне идеи?

Не отвечается хотя бы один — ты в режиме делегирования, не AI-first. Притормози.

SECTION 04
04

DAILY

CHECKLIST

Утро · процесс · коммит · вечер

04.01 // 0800–0810 · MORNING

Утро — 5–10 минут

  • Проверить evidence bundle вчерашних agent-задач (если работали асинхронно)
  • Открыть SDD текущей задачи; если нет — создать через /sdd-new
  • Определить risk class задачи /risk-classify
  • Зафиксировать acceptance criteria и инварианты до начала кода

Логика утра: интент → формальная спецификация до того, как агент начнёт писать код.

04.02 // FLIGHT_MODE · ACTIVE

В процессе работы

  • Plan first: /plan перед изменением >20 строк · read-only режим
  • TDD дисциплина: failing tests до кода · агент не меняет тесты
  • Subagent для verbose: explore/research/scan — в child-процесс, parent получает summary
  • Прерывать, а не одобрять: идёт не туда — ESC сразу
  • Не первое предложение: почти всегда улучшаемо
  • «Почему так», а не «сделай так» — переключает в comprehension-режим
04.03 // STOP_HOOK · GATE

Перед коммитом

  • Прошёл по diff построчно · могу объяснить каждую нетривиальную строку
  • Запустил /review для self-review
  • Собрал evidence bundle через /evidence
  • Все тесты зелёные без модификации acceptance criteria

⚠ Stop hook заблокирует завершение задачи без evidence bundle (§2.13).

04.04 // 1800–1805 · COOLDOWN

Конец дня — 5 минут

  • Зафиксировать lessons learned в CLAUDE.md или AGENTS.md (если паттерн повторяется)
  • Token spend — в пределах ожидания?
  • Что из сегодняшнего стоит автоматизировать как skill / hook / slash-команду?

Что повторилось дважды — кандидат на hook или skill/slash-команду.

SECTION 05
05

ANTI

PATTERNS

Пять способов саботировать себя. Избегай сознательно.

05.01 // DESKILLING_SPIRAL

Deskilling spiral

⚠ SYMPTOMS

  • Без AI не можешь отладить ошибку
  • Не можешь прочитать чужой код
  • Не спроектируешь модуль с нуля

⚕ TREATMENT

  • 1 спринт в квартал без AI (manual coding sprint)
  • Парное программирование без агента
  • Разбор AI-провалов как учебный материал, а не «фикс и забыли»
05.02 // BLIND_ACCEPTANCE

Blind acceptance

⚠ SYMPTOMS

  • Принимаешь 80%+ предложений автодополнения
  • Через час не помнишь, почему код такой

⚕ TREATMENT

  • Перед TAB — проговори про себя, что ждёшь
  • Совпало — отлично, но понял почему
  • Разошлось — либо твоё предположение неверно, либо AI ошибается. Стоп.
05.03 // CHAOS_MODE

AI everywhere · process nowhere

⚠ SYMPTOMS

  • Агенты везде, метрик нет
  • У каждого инженера свой стек
  • Результаты несопоставимы

⚕ TREATMENT · §7.1 PDLC

Platform-Centric: AI без IDP даёт фрагментацию, не leverage.

Единая IDP · golden path · shared skills/hooks.

05.04 // SPEC_DEBT

Specification debt

⚠ SYMPTOMS

  • Агент пишет код по тикетам в Jira, без SDD
  • Через 6 месяцев архитектура — лоскутное одеяло

⚕ TREATMENT

RULE: no SDD → no agentic implementation для R2+

/plan отказывается работать без approved SDD. Enforce через hook, не CLAUDE.md.

05.05 // PREMATURE_AUTONOMY

Premature autonomy

⚠ SYMPTOMS

Включил L4 (autonomous agents) до того, как стабилизировал L2 (evidence bundle, hooks, review). Долг — и технический, и governance.

⚕ TREATMENT · §3.6

L0 → L1 → L2 → L3 → L4 → L5

Перепрыгивание ступеней = накопление technical и governance долга.

SECTION 06
06

MATURITY

LADDER

L0 → L5 · что значит «AI-first» на каждом уровне

06.01 // FOUNDATION

L0 · L1 · L2 — фундамент

L0 Chat-assisted

AI вне SDLC. AI-first здесь невозможен — это L1 как минимум.

L1 Repo-context

AI знает соглашения репо (AGENTS.md). «Сначала спрашиваю агента, который знает контекст проекта».

L2 Verified assistant

Plan Mode + TDD + evidence bundle. «Каждая задача начинается с /plan, заканчивается /evidence».

06.02 // AGENTIC TIER

L3 · L4 · L5 — agentic tier

L3 Agentic workflow

Subagents, headless CI. «Issue открыт → агент строит plan и draft PR; человек ревьюит».

L4 Governed autonomy

Risk ladder, policy-as-code. «Agent действует сам в R0–R2; human-in-the-loop только для R3+».

L5 Autonomous PDLC

Event-driven factory. «Инженер ставит цели и проверяет evidence; день не начинается с открытия IDE».

⚠ Не «обогнать уровень» — переход L2 → L4 без L3 = деградация в хаос.

SECTION 07
07

TOKEN

DISCIPLINE

Токены — операционный ресурс, а не топливо «жги без меры».

07.01 // 4_RULES

Четыре правила

01 · ROUTING

Model routing. Рутина на дешёвой модели (Haiku/Mini), сложное — на мощной (Opus/o1). Экономия 60–70%.

02 · SCARCITY

Context as scarce resource. Targeted Grep/Read · subagent с return-summary для verbose explore.

03 · CACHE

Кеширование. Повторяющиеся system prompts должны попадать в prompt cache · до 10x экономия input.

04 · BUDGET

Token budget per task. Превышение плана на +50% = стоп, эскалация.

SYNC

AI-first — командная история, не сольный номер.

09.01 // HERO_MODE.LOG

Hero mode · vs · shared practice

⚠ WITHOUT SHARED PRACTICE

  • Alice — L4, subagents, headless
  • Bob — L1, не знает, что такое evidence bundle
  • Charlie — отключил хуки, ему «мешали»

Результат: PR Alice блокируется ревью Bob; Charlie деплоит баги.

✓ SHARED PRACTICE

  • Все на одном L
  • Единый golden path для всех типов задач
  • Skills / hooks — общие, в git
  • AI Champion обучает новеньких

Результат: скорость команды = скорость практики, не звезды.

READY?

DIAGNOSTIC

8 точек — ты AI-first или ещё нет.

11.01 // SELF_DIAGNOSTIC

Ты AI-first, если…

  • Каждая задача начинается с SDD или /plan, а не с открытия IDE
  • Можешь объяснить каждую строчку вчерашнего AI-кода
  • Evidence bundle закрывает каждую задачу
  • Verbose работу делегируешь subagents
  • Прерываешь агента чаще, чем одобряешь
  • Команда — на едином стеке промптов / skills / hooks
  • Раз в квартал — manual coding sprint
  • Знаешь свой текущий L (§3.6) и следующий шаг

6+ из 8 = AI-first practitioner · ≤3 = AI-fallback, стартовый пакет поможет

11.02 // 90_DAY_PROTOCOL

Roadmap — AI-fallback → AI-first

WK 01–02 · ONBOARD
  • Поставить hooks (destructive, evidence)
  • Прочитать AGENTS.md / CLAUDE.md
  • Первый SDD через /sdd-new
  • Завести личный dashboard
WK 03–08 · HABIT
  • TDD на каждой задаче
  • /plan перед изменениями >20 строк
  • Daily checklist в практике
  • Subagents (explore, test, review)
WK 09–12 · LEVEL UP
  • Headless CI: issue → draft PR
  • Risk ladder применяется автоматически
  • Manual coding sprint #1
  • L1 → L2/L3
