HARNESS > MODEL

Реверс-инжиниринг Claude Code: 98.4% кодовой базы — детерминированная обвязка, 1.6% — AI logic. Инженерная ценность — в permission gates, context management, tool routing, audit. Не в выборе модели.

01

OpEx

Выбор модели, Copilot-интеграции. Амортизируется со сменой поколения LLM каждые 6–9 месяцев.

02

CapEx

Свой Agent Runtime, Policy Hook Framework, Context Supply Chain. Накапливается; не зависит от вендора.

03

Соотношение

Доля CapEx в AI-бюджете определяет, кто выиграет окно 2026–2027. Это не «купить лучшие модели».

К 2029 внутренняя IDP даёт регулируемому банку то, что Anthropic / OpenAI / Cursor дают фронтиру: единый Agent Runtime, paved roads, policy enforcement, observability. Разница — compliance-by-design, а не post-hoc audit.

ТРИ КАПИТАЛЬНЫЕ ИНВЕСТИЦИИ

Горизонт 2026–2029 — это не закупка инструментов. Это построение трёх слоёв, которые накапливаются и не амортизируются со сменой моделей.

01 · СРЕДА ВЫПОЛНЕНИЯ

Платформа разработки (IDP)

Единая платформа с средой выполнения агентов в ядре: общий цикл, диспетчер инструментов, шлюз прав, песочница, восстановление после сбоев.

Что даёт: одинаковая семантика агента из Jira, IDE, CI/CD, портала. Смена модели не ломает процесс — обвязка переживает поколения LLM.

02 · УПРАВЛЕНИЕ

Политики и матрица риска (R0–R5)

Регуляторные требования выражены кодом: детерминированные хуки (PreToolUse, Stop, PII boundary) + шкала автономии от R0 (авто) до R5 (CAB).

Что даёт: соответствие EU AI Act, DORA, ISO/IEC 42001 — встроено в runtime, не делается «по факту инцидента». Аудит для регулятора готов всегда.

03 · КОНТЕКСТ

Цепочка поставок контекста

SDD, AGENTS.md, навыки и эвалы — как управляемый supply-chain объект с владельцем, версией, last-review и SBOM-метаданными.

Что даёт: знания команды накапливаются между сессиями и людьми; защита от context poisoning и устаревания; онбординг агентов и людей — в часах, не неделях.

Сегодня: DORA-замер для baseline · AI Champion назначить · мандат на 18 месяцев утвердить.

ПРОЦЕСС · ДВУХПЕТЛЕВАЯ МОДЕЛЬ

Классический SDLC сохраняет стадии, но меняется исполнитель каждой. Связь между петлями — через SDD как первичный артефакт и Evidence Bundle как протокол завершения.

// люди + AI-фасилитаторы · дни / недели

  • Ритуал: Mob Elaboration (30–90 мин)
  • Acceptance criteria: Given-When-Then
  • Участники: продакты, архитекторы, FDE
  • Декларативная, человеко-ориентированная

// AI-агенты под надзором · минуты / часы
  • Артефакты: код, тесты, deploy-artefacts
  • Ритуал: Mob Construction (2–4 часа, R2+)
  • Цепочка: Plan → Test → Coding → Review → Security
  • Участники: 6 ролей subagents
  • Императивная, агент-ориентированная

PROCESS · OPERATIONAL STANDARDS

СТАНДАРТЫ ОПЕРАЦИОННОЙ МОДЕЛИ

SPEC-AS-SOURCE

SDD — первичный артефакт

Изменение требования = update SDD → regenerate, не refactor. Код — производный, эфемерный.

EVENT-DRIVEN

Agent Factory

CVE-волны, regulatory campaigns, migration, deprecation — agentic chain без человека на «зелёных» путях.

HEADLESS CI/CD

IDE опциональна

Большая часть кода в репо никогда не открывается в IDE. The Decentering of the IDE состоялось.

EVAL-DRIVEN

Eval-suite до релиза

Каждая фича и инструмент имеет capability + regression evals до релиза. Не после.

EVIDENCE

Bundle обязателен

R1+ задача не закрыта без EB: diff, tests, lint, security scan, assumptions, risk class. Stop-hook enforced.

RISK LADDER

R0–R5 встроен в IAM

Agent identity и delegated OAuth scopes. Approval fatigue не используется как governance.

RISKS · 1 / 2 · EXISTENTIAL
// что должен лично удерживать руководитель

ТРИ ЭКЗИСТЕНЦИАЛЬНЫХ РИСКА

Десять рисков в полном регистре. Три из них — категории, которые делегировать вниз нельзя: они проявляются за горизонт 2–3 лет и убивают трансформацию изнутри.

01 DESKILL

Деквалификация инженеров

RCT Anthropic 2026: группа с ИИ — −17% на тесте мастерства. Наибольший разрыв — в задачах отладки. Через 2–3 года команда теряет способность работать без AI.

Митигация: mandatory manual sprints, hybrid code+explanation pattern, технические интервью без AI, pair programming для junior.
02 GOVERNANCE

Compliance theatre

93% prompts одобряются без изучения (Anthropic, март 2026). Если governance построен на user approval — он сломан by design. Регуляторный риск максимальный.

Митигация: primary control — hooks + policy-as-code. Risk Ladder R0–R5 → IAM. Approval — supplementary signal, не основа.
03 LOCK-IN

Vendor lock-in через инерцию

Концентрация на одной LLM делает уязвимым к pricing, model deprecation, политическим рискам. Горизонт 6–9 месяцев — стратегический.

Митигация: multi-model strategy by design (3+ в prod), MCP-абстракция, on-prem fallback. SLA harness: model swap < 2 недели.
